# Dual11Event

用 [MaaFramework](https://github.com/MaaXYZ/MaaFramework) 跑淘宝双 11「做任务赚能量」的日常任务：
点开任务面板 → 逐条做浏览任务 → 读秒结束自动返回 → 顺手领累计奖励。

一条命令扫完当天任务，适合每天跑一次。

## 它是怎么认屏的

不靠固定坐标。整条流水线是一台状态机，节点靠 OCR 文字和一张返回箭头模板判断当前页面：

落地页不是一进去就滑：先给 8 秒只看不滑，把该点的入口（搜索词、卡片）点掉，
再进下滑循环 —— 否则一记全长下滑会把「搜索发现」标题推出屏幕，就变成空滑。

| 看到的文字 | 判定 | 动作 |
| --- | --- | --- |
| `做任务赚能量` | 任务面板开着 | 分诊：先领奖励，再看有没有浏览任务，都没有就收工 |
| `浏览N秒` / `点击去逛` 副标题 | 该行是可自动做的浏览任务 | 按行偏移到同一行的 `去完成` 按钮点下去 |
| `滑块验证` / `安全验证` | 平台在拒绝自动化 | 立即收工退出，不碰 |
| `浏览15秒可领` | 落地页正在读秒 | 持续下滑，滑 6 秒识别一次 |
| `搜索发现` | 要求输入关键词的搜索页 | 不打字，点它下面第一条推荐词，再按顶栏「搜索」提交 |
| `极速版` / `快手` / `打开App` | 拉新装软件页 | 什么都不点，直接退出这一页 |
| `任务已完成` / `已得N` | 这条做完了 | 返回面板，由「浏览N秒」规则挑下一条 |
| `立即领取` | 累计任务奖励可领 | 点掉 |
| 找不到 `浏览N秒` 副标题 | 能自动做的都清了 | 正常结束 |

浏览任务落地页只有手指一直在下滑时读秒才走，所以「下滑」本身就是等待动作；
抬手间隔压到 `rate_limit` 的 300ms，一轮 6 秒，完成最多 6 秒内就会被抓到。

「下个任务」这个按钮存在，但**故意不点**：它把「下一条做什么」交回给游戏的顺序，里面就有
小游戏和邀请好友，进去之后退出时会冲到淘宝首页信息流，而 iOS 控制器没有 deeplink，
只能人来收拾。节点留在 `dual11.json` 里但没挂进任何候选链，要用再显式启用。

单页最多待 30 秒：读秒任务 15 秒就够，超过 30 秒还没认到完成态的就是走错了页面。
爬回面板有一条兜底阶梯，按顺序试：面板 → 活动页的 `去赚能量` → iOS 跨应用返回
`◀ 淘宝`（小游戏会整页跳去支付宝）→ 右上角 `X` → 左边缘慢速右滑 → 点左上角 `<`。
每级都有次数上限；边缘手势不是万能的，淘宝首页信息流不响应右滑，只能点那个箭头。
每级都有次数上限，爬不出来就正常退出，不会无限点。

坐标全部落在识别图上（短边缩放到 720），换机型不用改配置。

## 前置条件

1. **手机侧**：一台已配对的 iOS 设备，以及跑起来的 [XDeviceBridge](https://github.com/YJBeetle/XDeviceBridge) server。
   iOS 控制器不直接持有配对凭据，DDI 和设备会话都交给 xdb，所以 server 必须先起来：

   ```bash
   xdb devices          # 期望看到目标设备处于 connected
   xdb start-server     # 桌面客户端一般会自动拉起，这一步通常不用手动做
   ```

2. **MaaFramework**：需要带 iOS 控制器的构建（`MaaIOSControllerCreate`）。iOS 通道还没正式
   合进上游，所以目前取 `YJBeetle/MaaFramework` 的 `feat/ios-control-unit` 分支自行构建；
   合并进上游并出 release 之后，换成官方包即可。

## 预编译包

Actions 里会连带构建 MaaFramework。默认 `YJBeetle/MaaFramework` 的 `feat/ios-control-unit`
（iOS 通道还没合上游），合并后把 `maafw_repo` 改回 `MaaXYZ/MaaFramework` 即可，
两个值都能在手动触发时覆盖。
产出 `Dual11Event-macos-aarch64.zip`：解压后 `./Dual11Event` 直接能跑，动态库都在同目录的 `lib/` 里。
打 tag（`v*`）时会自动挂到对应 Release。

目前只出 macOS 包。这不是 xdb 的限制 —— 它的 iOS 协议是自己实现的，macOS / Linux / Windows
桌面和 Android 内嵌都能跑 server；只是这条打包链路还没在 Windows 上验证过 preset 和 MaaDeps。

## 构建

```bash
python3 scripts/fetch-ocr.py          # 拉取 PP-OCR v4 中文模型，带 sha256 校验
cmake -S . -B build -DMAAFW_DIR=/path/to/MaaFramework/install
cmake --build build
```

`MAAFW_DIR` 指向上面那个 install 目录（里面有 `libMaaIOSControlUnit` 和 `share/cmake`）。

## 运行

```bash
./build/Dual11Event
```

跑之前把手机停在活动页或任务面板都行。

| 参数 | 说明 |
| --- | --- |
| `-s, --serial UDID` | 多台设备时指定一台；只有一台在线可以省略 |
| `--xdb-port PORT` | xdb server 端口，默认读 `XDB_PORT`，再默认 17423 |
| `--budget SECONDS` | 单次运行硬上限，默认 3600 秒（够跑空一整个面板），防止卡住一直点 |
| `--assets DIR` | 资源目录，默认 `./assets` |
| `--entry NAME` | 入口节点，默认 `EarnEnergy` |

退出码 0 表示任务列表已清空，非 0 表示中途超时或失败。日志写在 `debug/maa.log`。

## 不会碰的东西

- 只点副标题写着「浏览N秒」的任务行。玩小游戏、邀请好友、`去兑换`（花天猫积分）、`去开启`
  （添加桌面小组件、开通知）都不会点 —— 面板里这些任务的按钮同样写着「去完成」，
  所以判定看的是副标题而不是按钮文案。
- 不输入任何文字。认到「确认收货 / 实付款 / 提交订单 / 立即支付 / 订单信息」这类交易页面，
  只按左上角返回，页面上的按钮一个都不碰。
- 遇到要求下载安装任何东西的引导页，流水线只会下滑和返回，不会去点安装；
  系统授权框会按「不允许 / 暂不」方向关掉。
- 认到「滑块验证 / 安全验证」这类真验证码就收工退出。判定必须带「验证」二字：搜索历史里就有「mgn7滑块」这种关键词卡片，只认「滑块」会把正常页面误判成验证码。
  真验证码是平台在明确拒绝自动化，硬闯既没用也可能伤账号，剩下的任务请手动做。

## 截图里有你的隐私

MaaFramework 默认把每次节点失败时的整屏截图存到 `debug/on_error/`，里面会有你的账号页、
订单页这类内容。`debug/`、`var/`、`config/` 都已在 `.gitignore` 里，但别用 `git add -f` 强行提交，
发仓库前也建议先删掉整个 `debug/`。

## 风险声明

这是给**自己的**设备做重复点击的脚本，没有别的用途。自动化点击不属于淘宝提供的交互方式，
活动规则随时会变，节点里的文案可能某天就对不上了（表现为跑不完然后超时退出，不会误点别的）。
账号被风控、活动收益作废之类的后果请自己承担；不想冒这个风险就别跑。
