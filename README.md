# Dual11Event

用 [MaaFramework](https://github.com/MaaXYZ/MaaFramework) 跑淘宝双 11「做任务赚能量」的日常任务：
点开任务面板 → 逐条做浏览任务 → 读秒结束自动返回 → 顺手领累计奖励。

一条命令扫完当天任务，适合每天跑一次。

## 它是怎么认屏的

不靠固定坐标。整条流水线是一台状态机，节点靠 OCR 文字判断当前页面，只有一处用模板
（弹窗中间那个不是文字的圆圈 X）。

落地页不是一进去就滑：先给 8 秒只看不滑，把该点的入口（搜索词、卡片）点掉，
再进下滑循环 —— 否则一记全长下滑会把「搜索发现」标题推出屏幕，就变成空滑。

| 看到的文字 | 判定 | 动作 |
| --- | --- | --- |
| `做任务赚能量` | 任务面板开着 | 分诊：先领奖励，再看有没有浏览任务，都没有就收工 |
| `浏览N秒` / `点击去逛` 副标题 | 该行是可自动做的浏览任务 | 按行偏移到同一行的 `去完成` 按钮点下去 |
| `滑块验证` / `安全验证` | 平台在拒绝自动化 | 立即收工退出，不碰 |
| `浏览15秒可领+400` | 落地页还在读秒，**没做完** | 继续下滑；这一格不动它 |
| `已得N` / `任务已完成` | 读秒归零，平台**自动到账** | 什么都不用点，直接回面板挑下一条 |
| `搜索发现` | 要求输入关键词的搜索页 | 不打字，点它下面第一条推荐词，再按顶栏「搜索」提交 |
| `极速版` / `下载App` / `安装后` | 拉新装软件页 | 什么都不点，直接退出这一页 |
| `立即领取` | 累计任务奖励可领 | 点掉 |
| 找不到 `浏览N秒` 副标题 | 能自动做的都清了 | 正常结束 |

浏览任务落地页只有手指一直在下滑时读秒才走，所以「下滑」本身就是等待动作。一轮是一记
**连续 15 秒**的拖拽（气泡要的就是「浏览15秒」），滑完扫一遍文字，没做完再滑一轮，
两轮 30 秒还没有结果就退出换下一条。

这里有个 MaaFramework 协议层的坑值得单独说：节点的 `timeout` 只管「动作做完之后反复扫
`next` 等命中」那一段时间，**节点自己不会被重复执行**。所以「滑 6 秒 + 等 30 秒」不是
5 次下滑，而是 1 次下滑加 24 秒干等 —— 抬手期间读秒根本不走。实测过一次 6 秒下滑之后
连续 33 秒画面静止、气泡文案一动不动，整条任务白跑。要连续滑就得把轮次显式串成
`TaskPage → TaskPage2`。

读秒气泡右侧那个小方块是**剩余秒数**（15 → 12 → 7 → 1），归零后整条横幅变成
「✅ 已得400能量」，再往后变成「已得400丨下单再得2000」。到账是平台自动做的，
页面上没有需要点的「领取」。

所以完成信号只能认 `已得N`。用 `可领` 当信号是错的：未完成的气泡本身就写着
「浏览15秒**可领**+400」，OCR 有时还会把它切成「浏览15秒」+「可领+400」两框，
于是节点会在读秒刚过半就去点一个不可点的框，点完退出 —— 计数器看着 1:1，能量一分没进。
更绕的是这个假命中让读秒永远走不完，`已得N` 就一次都不出现，看起来像死节点被删掉，
两个错误互相掩盖。只有逐帧看画面才拆得开。

同理，「下单再得 / 下单得N」也不能当危险词：它是任务**成功之后**横幅的下半句，
商品卡上也满是「下单得1744淘金币」，全屏识别里放这两个词等于把刚做完的任务判成
订单页逃走。危险页只留页面级的交易文案（`提交订单`、`实付款`、`立即支付` 这类，且都锚定整框）。

「下个任务」这类按钮存在，但**故意不点**：它把「下一条做什么」交回给游戏的顺序，里面就有
小游戏和邀请好友，进去之后退出时会冲到淘宝首页信息流，而 iOS 控制器没有 deeplink，
只能人来收拾。

单页最多待 30 秒：读秒任务 15 秒就够，超过 30 秒还没认到完成态的就是走错了页面。
爬回面板有一条兜底阶梯，认得到文字的先用文字（`去赚能量`、`◀ 淘宝` 跨应用返回、
右上角 `X`、弹窗中间的小圆圈 X、底部「我的淘宝」+ 权益行「淘金币」—— 这一条能自己走回活动页），
全都认不到时才按顺序降级用三个盲操作：点左上角 `<` → 左边缘慢速右滑 → `StartApp` 拉起淘宝。
每一级都有次数上限，用完降到下一级，最后正常退出，不会无限点。
顺序不能反：`StartApp` 不杀已运行的实例，页面卡住时它只是把应用重新聚焦、画面一动不动，
把它排在前面就是空转（实测 50 秒里白启 5 次）；而盲点 `<` 的框要罩住箭头的真实位置
（实测中心约 (42, 162)），框画高了十几像素就一直在点空气。

坐标全部落在识别图上（短边缩放到 720），换机型不用改配置。`roi` / `target` 的四元组是
`[x, y, width, height]` 而不是左上右下 —— 写错不会报错，只会被静默裁切成更大的区域，
顺带在日志里刷一堆 `roi is out of range` 警告。

## 前置条件

1. **手机侧**：一台已配对的 iOS 设备，以及跑起来的 [XDeviceBridge](https://github.com/YJBeetle/XDeviceBridge) server。
   iOS 控制器不直接持有配对凭据，DDI 和设备会话都交给 xdb，所以 server 必须先起来：

   ```bash
   brew install scrctl/tap/xdb
   xdb devices          # 期望看到目标设备处于 connected
   xdb start-server     # 桌面客户端一般会自动拉起，这一步通常不用手动做
   ```

   **版本要对齐**：MaaFramework 的 iOS 单元里链的是它子模块 pin 住的那个 xdb，server 跑太旧的
   版本会连不上。而且 server 是常驻后台进程，`brew upgrade` 之后它还在用老二进制，
   需要 `xdb kill-server --port 17423 && xdb start-server --port 17423` 重启一次。

2. **MaaFramework**：需要带 iOS 控制器的构建（`MaaIOSControllerCreate`）。iOS 通道还没正式
   合进上游，所以目前取 `YJBeetle/MaaFramework` 的 `feat/ios-control-unit` 分支自行构建；
   合并进上游并出 release 之后，换成官方包即可。

## 预编译包

Actions 里会连带构建 MaaFramework。默认 `YJBeetle/MaaFramework` 的 `feat/ios-control-unit`
（iOS 通道还没合上游），合并后把 `maafw_repo` 改回 `MaaXYZ/MaaFramework` 即可，
两个值都能在手动触发时覆盖。
产出 `Dual11Event-macos-aarch64.zip`：解压后 `./Dual11Event` 直接能跑，动态库都在同目录的 `lib/` 里。
打 tag（`v*`）时会自动挂到对应 Release。

目前只出 macOS 包。这不是 xdb 的限制 —— 它的 iOS 协议是自己实现的，macOS / Linux / Windows
桌面和 Android 内嵌都能跑 server；只是这条打包链路还没在 Windows 上验证过 preset 和 MaaDeps。

## 构建

```bash
python3 scripts/fetch-ocr.py          # 拉取 PP-OCR v4 中文模型，带 sha256 校验
cmake -S . -B build -DMAAFW_DIR=/path/to/MaaFramework/build/install
cmake --build build
```

`MAAFW_DIR` 指向上面那个 install 目录（里面有 `libMaaIOSControlUnit` 和 `share/cmake`）。

源码构建的 MaaFramework 会把 `find_dependency(OpenCV)` 转嫁给消费者，而 OpenCV 的配置在
MaaDeps 的 vcpkg 目录里、不在 install 树内。CMake 会按宿主平台在 `MAAFW_DIR` 上几级里自动
找到它（打印 `Using MaaDeps from: …`）；找不到时显式传 `-DMAADEPS_DIR=…/installed/maa-<arch>-<os>`。
官方 release 包是自足的，不需要这一步。

## 运行

```bash
./build/Dual11Event
```

跑之前把手机停在活动页或任务面板都行。

| 参数 | 说明 |
| --- | --- |
| `-s, --serial UDID` | 多台设备时指定一台；只有一台在线可以省略 |
| `--xdb-port PORT` | xdb server 端口，默认读 `XDB_PORT`，再默认 17423 |
| `--budget SECONDS` | 单次运行硬上限，默认 3600 秒（够跑空一整个面板），防止卡住一直点 |
| `--assets DIR` | 资源目录，默认 `./assets` |
| `--entry NAME` | 入口节点，默认 `EarnEnergy` |

退出码：0 = 面板里能自动做的都清空了；2 = 阶梯用完还是回不到活动页（或连续 20 次退出动作没换来任何进展）；3 = 手机侧隧道断了；1 = 预算到点或失败。
日志写在 `debug/maa.log`，节点失败时的整屏截图在 `debug/on_error/`。

## 不会碰的东西

- 只点副标题写着「浏览N秒」的任务行。玩小游戏、邀请好友、`去兑换`（花天猫积分）、`去开启`
  （添加桌面小组件、开通知）都不会点 —— 面板里这些任务的按钮同样写着「去完成」，
  所以判定看的是副标题而不是按钮文案。
- 不输入任何文字。认到「确认收货 / 实付款 / 提交订单 / 立即支付 / 订单信息」这类交易页面，
  只按左上角返回，页面上的按钮一个都不碰。
- 遇到要求下载安装任何东西的引导页，流水线只会下滑和返回，不会去点安装；
  系统授权框会按「不允许 / 暂不」方向关掉。
- 认到「滑块验证 / 安全验证」这类真验证码就收工退出。判定必须带「验证」二字：搜索历史里就有「mgn7滑块」这种关键词卡片，只认「滑块」会把正常页面误判成验证码。
  真验证码是平台在明确拒绝自动化，硬闯既没用也可能伤账号，剩下的任务请手动做。

## 截图里有你的隐私

MaaFramework 默认把每次节点失败时的整屏截图存到 `debug/on_error/`，里面会有你的账号页、
订单页这类内容。`debug/`、`var/`、`config/` 都已在 `.gitignore` 里，但别用 `git add -f` 强行提交，
发仓库前也建议先删掉整个 `debug/`。

## 风险声明

这是给**自己的**设备做重复点击的脚本，没有别的用途。自动化点击不属于淘宝提供的交互方式，
活动规则随时会变，节点里的文案可能某天就对不上了（表现为跑不完然后超时退出，不会误点别的）。
账号被风控、活动收益作废之类的后果请自己承担；不想冒这个风险就别跑。
